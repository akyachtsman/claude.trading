> Looking at a thread of Haiku answers, no times on them: "I'd like a timestamp on when the answers came in."

**STATE: client only — no migration, no deploy.** `desk_chat_history` already returned `created_at` for every row (it is in the column list its rows are built from, before and after `desk_022`), so the replay needed nothing from the server, and a live reply is stamped by the tab when it lands.

- **What is drawn:** ONE muted line, `p.ask-when`, directly under each answer and ABOVE the model line and the sources: `Oct 14, 12:32 PDT`. It has the model line's footprint and ink (`--color-text-secondary`, `--font-2xs`), and when a model line follows the two sit tight as one pair (`.ask-when:has(+ .ask-model)`; a browser without `:has` just keeps the ordinary gap). The tooltip is `Answer received 2026-10-14 12:32 PDT` — the year lives there.
- **Pacific, date always drawn (`askWhen` in `data.js`).** Like every clock on the desk it is pinned to `DESK_TZ`, never the viewer's zone. The date is NOT dropped for "today" (the news rows' rule): a thread runs across days and an omitted today would go stale across Pacific midnight with the tab open and nothing to recompute it. A December stamp reads `PST` and can be the evening BEFORE its UTC date (`2026-12-05T01:03Z` is `Dec 4, 17:03 PST`).
- **Which time:** a replayed answer carries the row's `created_at` — the moment the server stored it, written after the answer is complete (answer #164, in the last bullet, was stored at `02:03:56Z`, 19:03 PDT); a live answer is stamped when the reply lands in the tab, which is within a second of the same. A visitor's live answer is stamped too (no model line, nothing saved). A refused or stopped question is not an answer and is not stamped. The tab's own clock is used for a live stamp: the reply carries no time, and adding one is a `desk-ask` deploy.
- **A time that cannot be read draws nothing.** `askWhen` accepts only a string shaped like an ISO date-time (`YYYY-MM-DDTHH:mm…`) and one that `Date` accepts as a real date — a null, missing, empty, junk or numeric `created_at` AND a bare year (`new Date('2026')` is valid) or an impossible date shaped like one (`2026-13-45T25:99`) all return null, so the panel never prints `Invalid Date` or a confident wrong time. The fraction is cut to milliseconds first (Postgres returns microseconds; not every engine's `Date` parses past three digits).

## The sources footer is collapsed — owner, 2026-10-14

> "How do I get rid of all these?" (six CPI headline links under one answer) — then, offered *collapse* or *remove*: "Collapse them".

Each answer that cites the web used to draw up to six links in a row under it, always. They are now ONE muted line, `Sources (N)`, a native `<details>` drawn CLOSED (`appendSources` in `renderAsk`, `.ask-sources` in `styles/legacy.css`). It is the same function for an answer that has just arrived and for one replayed from the saved conversation, so both are closed.

- **N is the number of links actually drawn.** The page still looks at the first six sources only (`slice(0, 6)`), still draws only `http(s)` URLs (a `javascript:` or `data:` URL from a web result or a tampered memory row never becomes a link), and a footer with nothing drawable is not drawn at all — never `Sources (0)`.
- **Why `<details>`, not a script-driven toggle:** Enter, Space and a tap work with no code, the open state belongs to the element, and the `Sources (N)` text is the accessible name. The disclosure arrow is a CSS `::before` with empty alt text (decoration). The line is the muted secondary-text token (the Clear button's, already contrast-checked) — never the accent the links wear and never the gain/loss colours. On a touch screen the line is at least 32px tall.
- **Opening must not lose the links.** A `toggle` listener keeps what opened INSIDE the thread: it scrolls the thread (never the page, so no `scrollIntoView`) just far enough for the last link to show, and never so far that the `Sources` line itself leaves the top of a thread shorter than the list.
- **Not changed:** the sources are still stored with the answer (`desk_chat_memory.sources`) and `desk_chat_history` still returns them; nothing server-side moved. Removing them from the screen entirely was the alternative offered and NOT chosen — the original spec asked for a compact sources footer (FR-TR2, `specs/live-desk-assistant/`), and this keeps it one click away.
- **A limit that predates this change:** at 810px the Ask panel of a VISITOR (no switch, so no raised height cap) leaves the thread almost no height, so anything drawn in it is squeezed there, links included. The owner's panel keeps a usable thread (the model tier's `layout.css` cap). S70 measures the scroll behaviour as the owner for that reason.

Guarded by S70 and `tools/ask-model-tier-client-mutants.py --sources` (13 mutants, each caught).
