## A. Markup and layout
- **E1 — Panel in `.area-econ`** (the desk row's 4th slot, where the accounts used to be): a panel with the standard head — title "Economy", a data-state lamp `#econLamp` and an as-of stamp `#econStamp` (every panel carries both — the design signature), the span control (E3), then a list `#econList` of rows. One `<main>` landmark stays; no `innerHTML` anywhere — every dynamic string via `textContent`.
- **E2 — Width.** Keep the **232px** column. It fits if each row is TWO lines on the left and the chart on the right:
  `[label (line 1) / value + delta (line 2)] [chart 96×30]`. Budget at the desk's type sizes: content 208px (12px padding each side) = left block 104 + gap 8 + chart 96. The longest label is 12 characters (validator cap) ≈ 80px at 11px; `4.90%` + `−0.05` ≈ 78px at 12px — both fit 104 without truncation. A one-line row (label · value · delta · chart) needs ~290px and would take ~58px from Ask; not recommended. Seven rows × ~40px + head + span control ≈ 340px, well under the desk row's measured 927px (Markets stays the measuring column; see `docs/architecture/desk-row-layout.md` before touching `.desk-row` rules). Values NEVER clip: a clipped yield is a wrong yield.

## B. Span control
- **E3 — `#econTf`**, the shared `.seg` chrome exactly like `#wlTf`: buttons `1W 1M 3M 6M 1Y 5Y` with `data-tf` = `1w 1m 3m 6m 1y 5y`, `aria-pressed`, persisted in `localStorage` key **`econ_tf_v1`** (wrapped in try/catch — private mode), validated against the list on load. **No 1D** — the data has no intraday series (spec §6); say so in the control's `title`. Default **`1y`**: on 3M and shorter every monthly row falls back to its 6 latest readings, so 1Y is the shortest span on which all seven rows draw a real window.
- **E4 — Switching** calls `deskFeed('desk-econ', { range })` (a slice server-side, no upstream cost) and redraws. Drop any reply whose `payload.range !== econTf` — a slow 5Y reply must not repaint rows after the owner switched (the `#wlTf` rule).

## C. Rows
- **E5 — Row content** (`renderEcon(payload)`): label; value formatted with the row's `decimals` plus its `unit` (`4.90%`); delta signed with the same decimals (`−0.05`) — this is a change in **percentage points**, so no `%` sign on it, and it is coloured with the gain/loss tokens ONLY IF the owner wants direction colour (a rising yield is not a "gain"; default: neutral ink with a ▲/▼ glyph). `value`/`delta` null → em dash (the shared formatters already answer `—` for null — reuse them; `fmtPct(null)` must never print `+0.00%`).
- **E6 — The row's date**, beside or under the value, small: a **daily** row shows `Sep 30`; a **monthly** row shows the MONTH the reading is for — `asOf: "2026-08-01"` renders **`Aug`**, never `Aug 1` (that reads as a stale daily print). Format `asOf` by **string slicing**, never `new Date('2026-08-01')`: that is UTC midnight and renders as **Jul 31** in the Pacific clock the desk runs on.
- **E7 — Source**: `source === "treasury"` → a tiny `UST` tag (or the row `title`: "U.S. Treasury daily rate" (never "same day": before today's rate posts it is yesterday's)); `"fred"` → `FRED` / "FRED (lags 1–2 business days for yields)". Never imply a daily yield is today's when `asOf` is not today.
- **E8 — The chart**, to the RIGHT of the value block, drawn from `points` with the **same sparkline idiom as the watchlist tiles** (`buildSpark`-style polyline in an inline SVG, no axes, no vendor JS): x = index order (points are already oldest-first and thinned to ≤120), y = min/max of the row's own points with a little padding. `points: []` → no SVG (leave the slot blank). When `pointsNote` is present, show a muted 9–10px caption under the chart (`6 latest`) and put the full note in the row's `title`/`aria-label` so the owner knows why 1W of CPI shows half a year.
- **E9 — Status**: `stale` → keep the values, dim the row slightly and add `stale` to its title with `staleSec` as an age; `missing` → label + em dashes, no chart. Live mode is REAL DATA OR NOTHING: never fall back to demo rows while `DESK.mode !== 'demo'`.

## D. Lamp, stamp, poller
- **E10 — Lamp**: `Demo` in demo (S5 expects every named panel lamp to read exactly "Demo" — **update S5's "six named panel lamps" count** when this lamp joins). Live: `LIVE` when the last poll succeeded with `ok && !stale`; `STALE` when the poll failed, or `stale` is true, or `generatedAt` is older than 2 × the last `refreshInSec`. There is no EOD state — these are not price feeds, so call `liveLampFor` only if its `priceBound` argument is false, or write the three-way rule directly. The lamp AGES even when the poll fails, and rendering stays OUTSIDE the fetch `try` (`renderAfterFetch`).
- **E11 — Stamp**: "Checked HH:MM" from `generatedAt` via the Pacific clock (`fmtClock`) — the per-row dates (E6) say what the data is FOR; the stamp says when the desk last asked.
- **E12 — Poller**: its own timer, delay = `payload.refreshInSec` clamped to [30, 3600] s — the function already tightens it inside the 08:25–09:15 and 15:25–18:30 ET release windows and relaxes it at weekends; paused while the tab is hidden, re-armed on `visibilitychange`; on a failed poll retry after 60 s (fast retry) and lamp STALE. "Refresh now" (`#refreshNowBtn`) may pass `{ force: true, range }` like the other feeds.

## E. "NEW since you last looked"
- **E13** — `localStorage` key `econ_seen_v1` = `{ [id]: asOf }`. A row whose `asOf` is newer than its seen entry shows a small `NEW` chip. The seen entry is written only after the row has been ON SCREEN (IntersectionObserver ≥ 50%, document visible) for 10 s, so a release that lands while the tab is hidden is still NEW when the owner comes back. The very first load (no key) seeds silently — no wall of NEW chips. Do not drive this from the payload's `changed` bit: it is per-isolate best effort (spec §4) and a cold isolate says false.
