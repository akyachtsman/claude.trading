## Project Overview
- **Project name:** claude.trading — multi-account trading dashboard
- **Live URL:** https://akyachtsman.github.io/claude.trading/
- **Stack:** Static tier — plain HTML + CSS + vanilla JS on GitHub Pages (no
  build), confirmed. Dynamic data arrives two ways: public market data from
  anon-callable Supabase edge functions (session-aware cached; the nightly
  committed-JSON pipeline was retired 2026-07-13), and (when live mode is enabled)
  private data behind PIN-validated Supabase RPCs.
- **Branch policy:** Develop on a `claude/<name>` feature branch; PRs target `main`

### Load-bearing rules — read the topic file BEFORE editing these
Each line restates a rule the topic text itself marks load-bearing, an owner ruling or NEVER;
the reasoning and measurements are in the file named at its end (all under
`docs/architecture/`). The `overscroll-behavior` ban, watchlist paging and live-mode
real-data rules stay in Project-Specific Coding Standards below.
- Every clock is Pacific (`DESK_TZ` via `fmtClock` / `fmtBarT` / `newsWhen`) — never the viewer's locale, never raw UTC. → `data-and-clocks.md`
- The price lamp reads EOD, not LIVE, once the market is shut; a stamp's clock is when the DATA last changed (session close for price feeds), not the fetch. → `data-and-clocks.md`
- Every number formatter answers an em dash for null/undefined/NaN/±Infinity — `fmtPct(null)` must never print `+0.00%`. → `data-and-clocks.md`
- A news row dates itself (`Mon D` above the clock) whenever it is not from TODAY's Pacific calendar date; the age is deliberately NOT filtered; `utcHmToPt` stays as the pre-`ts` fallback. → `data-and-clocks.md`
- A feed lamp AGES even when its poll fails, and renders stay OUTSIDE the fetch `try` (`renderAfterFetch`). → `data-and-clocks.md`
- `NYSE_HOLIDAYS` ends in 2027 — extend it before 2028. → `data-and-clocks.md`
- `wb_sticky_v1.syms` is POSITIONAL and always exactly `WB_SLOTS` (100) long: never `filter()` it; nothing pins any more (loader, header Load box, roster click). → `charts-rail-and-slots.md`

An open question is answered as an anonymous VISITOR: no saved conversation read or written (`userId` is null — the `if (userId)` guards around the replay and the append), and under the PUBLIC `DEFAULT_SYSTEM` (it is in this repo) — the owner's live-edited `desk_system_prompt` row is NEVER read for a visitor (it is PIN-gated and the only copy of the current prompt; a visitor can coax a model into repeating what it was given — security review 2026-10-04), with `OPEN_SESSION_NOTE` after it LAST (it says the reader is not the owner), any `accounts` block in the request is deleted before the snapshot (the system prompt says the reader is the owner, so a forged block must not read as holdings), `verify` is ignored — armed per question OR forced by the `ASK_VERIFY=1` secret (it doubles the cost; Codex, PR #305) — the reply carries `open: true`. The client mirrors it: `deskAsk` sends NO `pin` key for a visitor; `renderAsk()` draws the composer whether or not the desk is unlocked, and the history replay, Clear, Verify, ⏱ and ⚙ exist ONLY when `DESK.authed` (all PIN RPCs); a stopped open question must not promise a history. `tools/ask-gate-check.mjs --mutants` (S59 for the client) is the guard; deploying means migration `desk_020` FIRST, then `desk-ask` (`verify_jwt` OFF, as before), then the client — an old server answers a PIN-less request 400. → `desk-ask-and-cron.md`
- **The desk PIN is remembered on the device (owner 2026-10-04: "keep it for accounts at the bottom but leave it unlocked for now"); the SERVER is still the gate.** `sessionStorage 'desk_pin'` stays the working copy every reader uses; `localStorage 'desk_pin_device_v1'` (`deskPinDeviceGet/Set`, `deskPinForget` in `data.js`) is the copy that outlives the tab. Boot reads the tab's PIN, else the device's, and VALIDATES it with `desk_login` — a definite `{ok:false}` (the PIN was changed) forgets BOTH copies, a failed call (network blip) forgets NOTHING and leaves the desk locked for now; success re-seeds the tab's copy and writes the device copy (an already-unlocked tab becomes an unlocked device). Unlocking writes both; a wrong PIN is stored nowhere; **Lock forgets both** (`deskPinForget`), otherwise Lock would unlock itself on the next reload. Residual, accepted by the owner: `localStorage` is shared by every page on `akyachtsman.github.io`, so a script on any of the owner's other Pages sites could read the PIN (it is brute-forceable through the RPC anyway). Never put the PIN, or a way to derive it, in this repo or `config.js`; "unlocked" is a device holding it, never the server skipping the check — the dashboard RPCs (`desk_get_dashboard` and the rest of the PIN set) stay PIN-checked. → `desk-ask-and-cron.md`
- `config/chart-watchlist.json` is a bare JSON array (no `_note`), deduped, capped at 40, cached 1 hour; an EMPTY `config/widgets.json` array means "none", not "use the defaults". → `config-and-widgets.md`

## Project-Specific Coding Standards
- **Live mode is REAL DATA OR NOTHING (owner ruling 2026-07-22):** no panel
  may ever render demo/fabricated data while `DESK.mode !== 'demo'` — a feed
  failure shows a blank/empty state with a STALE lamp and a fast retry
  (visibility-aware), or keeps the last good LIVE render. The demo generator
  is exclusively for `?demo=1`.
- Price-change percentages use **2 decimals** (finance convention) — a
  deliberate exception to the editorial whole-number rule; allocation-style
  percentages stay whole.
- All dynamic DOM text via `textContent` — never `innerHTML`.
- **All dialogs open through `openModal()`/`closeModal()` in `app.js`** (focus trap, Escape via the dialog's own close so a veto such as the dirty scheduled-ask warning still applies, backdrop click on the backdrop element, focus returned to the opener). Never add a per-dialog Escape or backdrop listener. `openModal()`/`closeModal()` also make the page behind the top dialog REALLY `inert` (`syncModalInert()`: every sibling along the chain from the top backdrop up to `<body>`, never the chain itself; tracked in `modalInerted`, and an `inert` that something else set is never stripped). `inert` must be lifted BEFORE `opener.focus()` — `focus()` on an inert node silently does nothing.
- Series colors/order are CVD-validated (`--color-series-1..3`): do not reorder.
- Gain/loss colors are P&L-only, never decorative — the ONE owner-ruled exception is the digits of the Economy panel's change figure (see its colour rule above). Errors and status use
  `--color-danger` / `--color-status-live`; dark-context loss TEXT uses
  `--color-loss-text` (`--color-loss` #e11d1d is 3.87:1 on surface-2 — candles and
  bands keep `--color-loss`).
- Every panel carries a data-state lamp + as-of stamp (the design signature);
  new panels must too.
- **NEVER use `overscroll-behavior: contain` (the shorthand) on this page.**
  The owner reported the same fault three times across 2026-08-07: the mouse
  wheel dies over a panel and the page only scrolls from the far edges of the
  screen. `contain` stops a scroll chaining to the page — right at the END of a
  long list, but it applies just as hard when the container has NOTHING to
  scroll, and then it simply eats the wheel. **Chromium chains regardless, so
  this never reproduces in a Chromium harness** (the sandbox's WebKit —
  installable through `.github/scripts/browser-ladder.js`, see Sandboxed local runs —
  has not been used to exercise wheel chaining), which is why two rounds of "verified fixed" were wrong. The last
  holdout was `.ask-thread`, empty before the first question and therefore
  invisible to every scan — it needs a live AUTHED session to exist at all.
  A scan is only meaningful if it checks both axes and every mode: an earlier
  one tested `overflowY` alone and reported zero traps while `overflow-x`
  scrollers went unexamined. Since 2026-10-04 there is NO `overscroll-behavior` on
  the page at all: the watchlist bands, which carried the axis-scoped
  `overscroll-behavior-x: contain` (a sideways swipe off a band's end must not
  trigger browser back-navigation), no longer scroll sideways — they wrap. S42
  still scans every rule and inline style for the shorthand and any `-y` form.
  Only those were ever banned.
